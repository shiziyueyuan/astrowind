# 第 6/10 轮：只读博客与本机写作间

用户确认通过本机管理页上传 Markdown，保存文件并更新本地预览；公开博客不允许评论或回复。随后明确要求推送到自己的 GitHub Fork 并提前部署 GitHub Pages。其余开发轮次保留，未宣称全部完成。

## 使用

双击项目根目录的“打开写作间.cmd”，浏览器打开 http://127.0.0.1:4324 。选择或拖入一份 `.md` 文件，也可直接写正文。普通 Markdown 不需要预先填写 YAML：标题可从一级标题或文件名提取，文章地址会自动生成。

选择正文语言、分类、日期及地址，然后保存草稿或发布到本地预览。本地发布会更新博客列表和阅读页。确认内容后点击“同步到公开网站”，只提交公开博客目录，推送到已确认的 `shiziyueyuan/astrowind` 主分支；GitHub Actions 完成后公开网站更新。管理页不把“已推送”误报为“已部署”。

本机管理页绑定 127.0.0.1:4324，不包含在 Pages 的静态产物中。写入请求校验同源与临时令牌，不接收远程匿名投稿。草稿位于项目外的 `work/journal-studio/drafts`；旧版本备份位于同级 backups。修改已公开文章的草稿保留公开旧版本，发布失败保留文稿并尝试恢复预览。

## 公开阅读

- LAB 显示最新文字与博客入口；三语列表提供标题、分类、日期、原文语言及搜索。
- 独立文章页支持 Markdown 标题、列表、引用、代码、表格和图片，并按二级标题生成目录。
- 同地址的中英日文稿互相关联。只有一种正文语言时，三语界面展示原文并明确提示没有对应译文，不编造翻译。
- `note`、`log`、`essay`、`experiment` 分别对应闲言碎语、日志、观点、实验。
- 所有公开页面仅供阅读，没有评论组件、回复表单、留言 API 或评论服务。
- 管理页接收 `.md`，不接收 MDX；文章中的原始 HTML 作为文字显示，危险链接协议不可执行。
- 既有三份开发草稿继续留在本机，不擅自公开；首次上线没有虚构文章。

GitHub Pages 只承载构建后的公开页面、已确认的项目媒体和联系方式；模板参考页面保留在 examples，不生成公开路由。
